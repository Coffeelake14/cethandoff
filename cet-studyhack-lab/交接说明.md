## 2. 主入口与完整流程

阅读视图顶部有两个子页签：**错因实验室**（默认）/ **阅读工具**。

### 2.1 错因实验室（默认入口）

首屏有醒目的「开始练习」和「使用自带材料」。免登录即可走完整流程：

1. **选材料**：3 篇人工核对答案的预置练习（范围扩大 / 因果倒置 / 态度变化），或自带材料。
   自带材料支持**拍照导入原文与题目**：结构化识别会提取文章、题号、题干与四个选项；识别到多道题时出现题号选择，
   点选后自动填入题干与 A/B/C/D（仍可修改）。原文框保留识别换行，校对后再切句；照片不进入草稿。
2. **作答**：选 A/B/C/D；在上方原文中点选 1–3 句作为依据；选信心（高/中/低）。
3. **短提示**：提交后先只展示**不泄露答案**的短提示（不出现正确选项字母或其同义改写）。
4. **重答**：回到原文复核后重新选答案并提交。
5. **结果**：
   - 首答与正确项、重答结果；
   - 「你选的证据」与「正确证据」两栏，均可点击**跳回原文并高亮**；
   - 错因证据卡：错误类型标签、并列对照（例如原文 `Some` ↔ 选项 `always`）、简短解释；
   - 答对但依据不对 / 信心不足也会明确反馈；
   - 证据不足时显示「证据不够，暂时无法诊断」，提供「重选证据 / 换一篇」。
6. **同类新题**：陌生的同类材料；预置题直接使用人工核对的同类题，自带题从服务端**已核题库**匹配。
7. **本次结果**：只基于本次作答的事实清单（首答、错因、重答、同类题、依据是否对齐）与一句下一步建议。
   明确写「不代表整体水平，也不是分数预测」。

学习草稿和进度在当前浏览器 `localStorage`，没有账号同步。使用 AI 时，提交的材料会发送给 Qoder Cloud Agents。本站私有数据库只存服务额度、资源绑定和脱敏运行记录。

### 2.2 阅读工具（保留给只看翻译或生词的用户）

- 可粘贴原文，也可**拍照导入原文**（`target:"reading"`）：浏览器压缩后调用 `scan` 识别印刷体/手写英文，
  识别结果填入原文框并允许先修改；照片不写入草稿。
- 粘贴原文后**按需**点「全文翻译 / 重点生词 / 长难句」，每次只请求一个短结果。
- 长材料自动分段翻译（前端每段 ≤1100 字符），状态显示「第 i/n 段」；某段失败只重试失败段，**已加载段保留**。
- 生词可导出默写清单（保留）。
- 加载 / 失败 / 重试状态在每个卡片内明确展示；连接状态只反映后端接口，AI 功能另读能力开关。失败或部分生成均按实际进度显示。
- 预置练习标为原创题。自带题区分用户提供的参考答案和 AI 判断。

### 2.3 结构化识图（自带材料 / 写作 / 翻译）

三类入口复用同一个压缩、`scan` 与校对链路（`structured:true`）：

- **自带材料**：结构化提取 `passage + questions[{no, stem, options[A-D]}]`，导入第一题并提供题号切换。
- **写作**：`prompt_material` 只放印刷体作文要求，`student_answer` 只放手写作文；自动填入题目框与作文框。
- **翻译**：`prompt_material` 只放中文原题，`student_answer` 只放手写英文译文。

1. 入口支持手机相机 / 相册、桌面拖拽、Ctrl+V 粘贴；JPG / PNG / WebP，HEIC 需先转 JPG。
2. 浏览器先按 EXIF 方向解码，再旋转（可点「旋转 90°」重拍前校正）并压缩：最长边 2000px、JPEG q≈0.88，
   目标 <1.8M 字符 Base64（远低于官方单张 10 MiB 限制）。
3. 原图与识别文本并排展示；窄栏（估分侧栏）自动改为上下堆叠。黄色高亮 = 模型标记的不确定片段，
   用户必须在下方文本框完成校对。
4. 只有用户点击「开始估分 / 进入作答」才进入第二阶段；评分阶段只发送校对后的文本，**不重复上传原图**。
5. 识别失败区分超时、额度不足、模型不支持图片、格式错误、没有文字；保留「重试识别」。
6. 同一张压缩图的 SHA-256 在浏览器与 Function 内用于短期缓存；缓存命中返回 `cached:true`，
   不创建新 Session、不消耗 credits。点「重试 / 旋转」会带 `bypassCache` 强制重识别。
7. 「移除照片」只清预览与识别结构，不清已填入的文字；已有文字时再拍照会先确认覆盖。

照片仅在内存中用于当次请求，**不写 localStorage、不落盘、不入库**；文本、题干与选项仍按现有草稿键保存。
OCR 服务端只保留校验后的 JSON 结果到进程内 LRU（最多 32 条），不保留图片字节。

## 5. 架构与数据流

```
浏览器 (web/)
   │  同源 fetch，Accept: text/event-stream
   ▼
Qoder Sites Function  /functions/v1/app?action=<train|explain|transfer|grade|recommend|scan>
   │  handler.mjs：方法/大小/输入校验 + 限流 + SSE 编排
   │  cloud-agents.mjs：QCA Managed API
   ▼
Qoder Cloud Agents  https://api.qoder.com.cn  (apiPathPrefix /api/v1/cloud)
   │  无状态：每次请求一次性 Session
   ▼
模型流式输出 → handler 转成应用 SSE 帧 → 浏览器渐进渲染
```

- **无数据库、无登录、无持久会话**。每次 AI 请求新建一次性 Session；`resources.mjs` 用 Cloud metadata
  指纹对账并缓存 Agent/Environment，single-flight 防并发重复创建。
- **action 契约**：
  - `train`：自带题的证据诊断，一次性短 JSON（不出流式文本）。
  - `explain`：按需单节（`translation | vocab | grammar`），流式 Markdown；前端负责分段。
  - `transfer`：从服务端已核题库按错因返回同类题（不走模型）。
  - `grade`：写译短 JSON 反馈（含分数、档位、是否具备切题/信息覆盖材料、逐句错误、错误类型统计、改进建议）。
  - `scan`：照片 → 文字或结构化文档 JSON（OCR，不评分）；`target` 支持 `reading | writing | translation`，
    `structured:true` 时返回题型、原文、题目、题干与选项、学生作答、不确定片段。图片以 Base64 image content block
    发给多模态模型；阅读上限 12000 字符，写译上限 4000 字符；10 分钟内同图复用结果。
  - `recommend`：从内置资料检索，校验引用后返回建议。
  - 旧的 `analyze`（一次返回全文翻译+词表+选项+长难句）已移除。
- **scope profiles**（系统提示词不同，必须分开缓存）：
  - 阅读工具：`cet-reading-tool:prod:cn`（explain）
  - 错因诊断：`cet-reading-train:prod:cn`（train，strict JSON）
  - 估分：`cet-score-estimator:v2:prod:cn`（grade / recommend；v2 因新增逐句批改提示词）
  - 拍照识别：`cet-writing-scan:v2:prod:cn`（scan，结构化识图；v2 因新增输出契约）
  - 旧的 `cet-reading-assistant:prod:cn`、`cet-score-estimator:prod:cn`、`cet-writing-scan:prod:cn`
    新代码不再使用；云端旧 Agent 保留，勿删。
  - 改系统提示词会改变指纹 → 会新建 Agent；注意云端 Agent 数量。
- `QODER_PAT` 只在 Function 内经 `Deno.env.get('QODER_PAT')` 读取，绝不进浏览器、绝不写进 `secretNames`。
- 拍照功能绑定 `CET_SCAN_MODEL`，该 ID 必须在当前账号启用列表中。模型目录声明不能代替实测，也不会回退到通用模型。
  识别结果分别显示 `model`、`visionDeclared`（目录是否声明视觉能力）和 `modelSource`。

### 应用 SSE 帧契约

| type | 含义 |
| --- | --- |
| `status` | 阶段状态（`state` / `message`） |
| `delta` | 增量文本（`text`），仅 explain |
| `replace` | 整段替换文本（`text`），仅 explain / recommend |
| `result` | 结构化结果：train 诊断 / grade 评分 / scan 转写 |
| `done` | 结束（`state`：`completed` / `partial`） |
| `error` | 错误（`code` / `message`） |

心跳：每 15000ms 发 `: ping`。`MAX_STREAM_MS=120000`，但每个新请求都足够短，正常不会接近网关截断窗口。

## 6. 错因诊断契约与证据校验

### 6.1 `train` 输入

```json
{
  "level": "CET4|CET6",
  "material": {
    "sentences": [{ "id": "s1", "text": "..." }],
    "question": {
      "stem": "...",
      "options": [{ "key": "A", "text": "..." }]
    }
  },
  "attempt": {
    "choice": "A",
    "evidence": ["s5"],
    "confidence": "high|medium|low",
    "referenceAnswer": "B"
  }
}
```

### 6.2 `train` 输出（短 JSON）

```json
{
  "answer_correct": false,
  "chosen": "A",
  "correct_option": "B",
  "error_type": "scope_expansion",
  "student_evidence_ids": ["s5"],
  "correct_evidence_ids": ["s5", "s6"],
  "english_diff": { "left": "Some", "right": "always" },
  "hint": "不泄露答案的短提示",
  "explanation": "1–2 句中文错因",
  "confidence": "high",
  "alignment": "aligned|misaligned|unknown"
}
```

支持的错因：`scope_expansion`（范围扩大）、`causal_inversion`（因果倒置）、`attitude_shift`（态度/语气变化）、
`detail_mismatch`、`not_supported`、`evidence_insufficient`、`right_answer_wrong_evidence`、
`right_answer_uncertain`、`none`。

### 6.3 服务端与前端双重校验（硬规则）

- 服务端只接受 `s\d+` 形式的句子 ID，过滤所有不在原文中的 ID；`correct_option` / 参考答案不合法则整次诊断失败。
- **学生证据以浏览器实际点击的句子为准**，不信任模型回显；答案是否正确由确认后的正确项重新计算。
- 前端再次按原文 ID 过滤；**展示的引句一律从原文按 ID 取文本，从不展示模型返回的引句字符串**。
  ID 找不到 → 不展示该引句；正确证据为空 → 「证据不够，暂时无法诊断」。
- 英文并排对照只有在：`english_diff.left` 出现在正确证据句、`english_diff.right` 出现在所选/正确选项时
  才渲染；否则只显示文字诊断。`dev/test-lab.mjs` 会校验所有预置题/题库的对照是否真实存在。
- 答对但依据不在关键句 → `right_answer_wrong_evidence`；答对、依据对齐但信心低 → `right_answer_uncertain`；
  完全正确 → `none`。
- 短提示不得出现正确选项字母；前端只展示短提示，重答后才展示诊断。

### 6.4 预置题与同类题

- `web/lab-data.js`：3 篇原创预置练习，每篇自带同类型同类题；答案与证据人工核对。
- `functions/lab-bank.mjs`：服务端已核同类题库（与预置题的同类题内容对应，需保持同步；`test-lab` 同时校验两边）。
- 预置题诊断**完全本地计算**，不调用模型，保证离线示例稳定；自带题才走真实 AI。
- 结果页文案统一为「本次练习结果 / 本次作答」，不做能力评估或分数预测。

## 7. 估分可信度（本轮修正）

- 去掉用户界面与备考建议中的**通过概率百分比**和暗示官方估分的表述。

  `dev/test-engine.mjs` 有回归断言：这些字段必须不存在。
- 保留官方「报道分→百分位」表插值（非线性），但明确 `RAW_NORM` 均值和标准差是**经验假设**，不是官方校准值。
- 写译 AI 反馈契约：

### 7.1 拍照识别契约（`scan`）

输入（`POST`，JSON）：

```json
{
  "target": "reading|writing|translation",
  "level": "CET4|CET6",
  "structured": true,
  "image": "data:image/jpeg;base64,...",
  "bypassCache": false
}
```

也接受纯 Base64 + `mediaType`。`structured:false` 时沿用旧文本契约
`{"text":"...","confidence":"high|medium|low","notes":"..."}`；`structured:true` 时输出：

```json
{
  "kind": "reading|writing|translation|other",
  "text": "整页可见文字",
  "passage": "阅读文章（仅 reading）",
  "questions": [{ "no": "46", "stem": "...", "options": [{ "key": "A", "text": "..." }] }],
  "prompt_material": "作文题目 / 翻译中文原文（仅写作/翻译）",
  "student_answer": "学生手写作文 / 译文（仅写作/翻译）",
  "uncertain": ["原文中真实出现的连续片段"],
  "confidence": "high|medium|low",
  "notes": "...",
  "cached": false,
  "usage": { "modelCredits": null, "sandboxCredits": null, "totalCredits": null, "requestCredits": null },
  "meta": { "model": "...", "visionDeclared": false, "modelSource": "verified-env", "durationMs": 1234 }
}
```

- 只做忠实识别与结构提取：不评分、不翻译、不纠错、不补全、不答题；看不清写 `[?]`，不确定片段进 `uncertain`。
- 服务端按 `target` 只保留适用字段：reading 不保留 `prompt_material/student_answer`，写译不保留
  `passage/questions`；每道阅读题必须恰好 4 个 A/B/C/D 选项且题干有效，否则该题被丢弃（不补造）。
- `uncertain` 必须逐字出现在 `text/passage/student_answer` 中，否则丢弃；最多 20 条。
- 截断上限：reading 12,000 字符；writing / translation 4,000 字符；题目最多 20 道；题干 ≤500 字符；选项 ≤300 字符。
- 服务端校验：target 必填；仅 `image/jpeg|png|webp`；Base64 长度 ≤6,000,000、解码 ≤4MB；
  **magic bytes 必须与声明的 MIME 一致**（防止把任意内容塞进模型请求）。
- 浏览器先按 EXIF 方向解码、支持旋转，再压缩：最长边 2000px、JPEG q≈0.88、目标 ≤1,800,000 字符；原图上限 20MB。
- 同图去重：浏览器与 Function 各用压缩后字节的 SHA-256 做 10 分钟缓存（Function 最多 32 条，仅存校验后的 JSON，
  **不存图片**）。缓存命中返回 `cached:true`，不创建 Session、不计入 AI 限流；`bypassCache:true` 强制重识别。
- 空照片或识别为空 → `ai_scan_empty`；JSON 不合法 → `ai_scan_invalid`；模型拒绝图片 → `ai_vision_unsupported`；
  上游额度不足 → `ai_quota_exceeded`；超时 → `ai_timeout`；均不填充文本框。
- 前端两步走：先识别并校对（原图 + 文本、不确定高亮），确认后再诊断/评分；评分只发文本，不重复发图。
- `usage` 来自官方 SSE 的 `session.usage`（累计 credits）与 `span.model_request_end.model_usage.credits`（本次调用）；
  未返回时保持 `null`，UI 显示「服务端未返回用量」，不估算。

### 7.1.1 官方接口依据（Qoder CN）

- 图片内容块：`{"type":"image","source":{"type":"base64","media_type":"image/png|image/jpeg|image/webp|image/gif","data":"<纯 Base64>"}}`；
  也支持 HTTPS URL 与已上传 `file_id`。单张 Base64 ≤10 MiB、宽高 ≤8000px、每条 `user.message` ≤100 张，
  且 **Session 必须使用支持图片输入的模型**。
- 会话：`POST /api/v1/cloud/sessions`（agent + environment_id）→ `POST /sessions/{id}/events`（`user.message`）→
  `GET /sessions/{id}/events/stream`（SSE）；`session.usage` 提供 `model_credits/sandbox_runtime_credits/total_credits`。
- 模型：`GET /api/v1/cloud/models` 只返回 `id/display_name/is_enabled/price_factor/max_input_tokens` 等，
  **没有视觉能力字段**；因此本包把“该模型能否读图”作为部署后必须用真实照片验证的项，而不是代码可证明的项。
- 文档入口：<https://docs.qoder.com/cloud-agents/sessions>、<https://docs.qoder.com/cloud-agents/api/sessions/events/send>、
  <https://docs.qoder.com/cloud-agents/api/sessions/schemas>、<https://docs.qoder.com/cloud-agents/api/models/list>。

### 7.2 写译逐句批改契约（`grade`）

在原有 `score/band/relevance/comment` 基础上新增：

```json
{
  "writing": {
    "errors": [{ "quote": "原文片段", "type": "spelling|grammar|word_choice|collocation|structure|coherence|punctuation|content", "fix": "...", "note": "..." }],
    "stats": { "grammar": 2 },
    "suggestions": ["..."]
  },
  "translation": {
    "errors": [{ "quote": "原文片段", "type": "omission|misread|grammar|word_choice|expression|punctuation|content", "fix": "...", "note": "..." }],
    "stats": { "grammar": 1 },
    "suggestions": ["..."]
  }
}
```

- `quote` 必须能在学生文本中定位；服务端按原文切片返回，找不到的整条丢弃（不展示凭空修改）。
- 写作无作文题目时禁止 `content` 类错误；翻译无中文原文时禁止 `omission/misread`；`relevance` 仍由服务端控制。
- 每模块最多 12 条错误、3 条建议；`stats` 由服务端按保留的错误计数，不信任模型自带统计。
- 结果附 `usage/meta`，UI 显示本次评分耗时与 credits。

## 8. 阅读长输出截断修复

交接文档原来记录：Sites 网关约 60s 截断，旧 `analyze` 一次返回全文翻译 + 8–15 生词 + 全部选项 + 2–3 长难句，
真实运行常在 61s 被截断。本轮改为：

- `analyze` 移除；阅读训练只请求**当前一题的必要字段**（`train` 短 JSON）。
- 翻译 / 生词 / 长难句拆成三个独立短请求（`explain`），用户点哪个加载哪个。
- 翻译在前端分段（`CHUNK_SIZE=1100` 字符），逐段请求，显示「第 i/n 段」。
- 失败时只重试失败段，**已加载段保留**；生词/长难句各自有重试，不互相影响。
- 加载 / 失败 / 重试状态在卡片内可见；服务端功能开关和请求结果决定用户可见状态。
- 生词导出保留（隐藏 `<!--VOCAB ... VOCAB-->` 解析）。
- 本地夹具只在 `dev/`；正式页面显示原创练习及实际题量。

> 即使以后发布，单次请求的输出也远小于旧版；但网关 60s 限制本身仍存在，不要重新引入「一次返回全部」的长请求。

## 10. 已知限制与未验证项

1. **真实云端未验收**：原站点在另一账号名下。请按 §9 和 §11.3 使用原账号走查。
2. **分段翻译的风格一致性**：各段独立请求，术语/语气在不同段之间可能有细微差异；如需完全一致，
   可在发布后用同一 Session 续写（当前特意不用，以换取短请求和可重试）。
3. **本地 fake cloud 的钩子**：`FAILTEST`（一次失败后成功）、`NOEVIDENCE`（模型引用不存在的证据 ID）
   仅在 `dev/` 中，产品代码没有这些分支；不要把它们部署或写进用户文档。
4. **限流**：数据库计量跨实例生效。进程内 IP 限速仅在受信转发模式启用，每实例并发另外受限。
5. **持久化**：学习资料和进度在当前浏览器，跨设备与清缓存后无法恢复。私有数据库只保存运行和费用保护记录。
6. **预置题与题库双份维护**：`web/lab-data.js` 与 `functions/lab-bank.mjs` 内容对应；改一处要同步另一处，
   `node dev/test-lab.mjs` 会校验两边。
7. **内置浏览器视口窄**（本机 525px）；本轮拍照与内联入口用无头 Chrome 在 1280×900 与 390×844 两种视口走查
   （含真实文件上传），真实手机仍需在发布后手测（相机直拍、相册、竖拍方向）。
8. 旧的公开页面已显示阅读错因实验室。它的 `health.mode=live` 只反映部署模式。新版健康接口只返回连通状态。
9. **拍照识别依赖已实测模型**：功能开关首先要求人工登记验证。模型必须在当前账号的启用清单中。模型目录是否声明视觉能力单独记录为 `visionDeclared`。
10. **真实手写照片未验证**：本地只验证了图片块结构、校验与 UI；真实识别准确率、反光/模糊、竖拍方向、延迟
    需用真机照片复验。HEIC 不在支持范围（前端 `accept` 仅 JPG/PNG/WebP），可让用户截图或用系统分享转 JPG。
11. **OCR 换行会影响切句**：自带材料识别后先落进可编辑原文框，再按换行/标点切句；识别把一段拆成多行时，
    句子 ID 会变多。做题前应检查并整理换行，避免证据句被切碎。这一点已在 UI 中以「识别后自动填入，可先修改」提示。

| 翻译、生词、长难句 | 输入两篇不同原文，核对语义、数字、专名和原句引文。验收长文分段、失败和重试 |
| 写译反馈与估分 | 核对原文引句与修改建议，有题目时才判断切题，降级后页面明确显示「按自评估算」 |
| 备考建议 | 核对引用对应的资料条目和实际链接，检查建议与输入的薄弱项一致 |
| 拍照 | 覆盖印刷体阅读、双栏、手写写作、手写翻译、旋转、模糊和无关图片。核对题号、A/B/C/D、原题与作答、原始拼写及校对后导入 |
| 公网费用保护 | 在受限同源环境确认签发与复用、无票拒绝、配置缺失关闭、预算耗尽返回 429、并发不会超预留，正常和失败请求按实际返回用量记账 |

每条记录填写环境或发布版本、时间、操作、样本来源、预期、实际结果、`X-Request-Id`、响应模型、耗时及真实 credits。用量缺失填写「未返回」。终止、失败和部分生成各按实际状态记录。账户能查到的 Cloud Session ID 仅用于内部对账，交接记录用站点请求 ID。

`dev/live-vision.mjs` 可对账号的明确模型 ID 做图像输入探针，探针结果仍需逐字对照。传入 `--model` 和自备照片。
`node dev/accept-live.mjs https://<受限验收域名>` 只做一笔真实翻译冒烟测试。若网关拦截脚本，直接在该域名的浏览器页面内验收。
确认照片和文本在平台内的保留、归档与删除能力。归档会改变 Session 的可见状态，不能用来承诺数据已经删除。

## 13. 安全红线（不变）

- `QODER_PAT` 平台托管、**仅服务端**：永不暴露给浏览器 / 聊天 / `secretNames`；永不要求用户粘贴。
- `dev/` 夹具、fake cloud、测试文件**绝不部署**。
- 服务端必须校验 method / size / input；不暴露通用 authenticated proxy。`scan` 还必须校验 base64、解码体积与 magic bytes，声明类型与实际字节不符一律拒绝。
- 开启 qoder 后端 / 创建 PAT 需**用户明确确认**（主站已在早期授权并 provision，复用即可；新账号 fork 才需重新确认）。
- 打包分发**不含任何密钥**。
- 预置题与题库内容为原创；不要混入未授权的真题原文。
